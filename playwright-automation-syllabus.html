Playwright Automation Learning Syllabus

Goal: By the end of this syllabus, you should be able to understand this DS7 automation repository, run existing Playwright scripts, debug failures, modify selectors and waits, add new automation flows, run PM2 long-running jobs, and maintain SRN/logging workflows safely.

Phase 1 — Basic Foundations

1. Learn what browser automation is

Browser automation means controlling Chrome, Edge, or Firefox with code. Playwright can open pages, click buttons, fill forms, wait for UI elements, upload files, read URLs, take screenshots/videos/traces, and run tests repeatedly.

Key terms

  • Test spec
  • Locator
  • Selector
  • Browser context
  • Page
  • Headed vs headless
  • Assertion
  • Timeout
  • Trace
  • Screenshot
  • Retry

First Playwright pattern

import { test, expect } from "@playwright/test";

test("basic example", async ({ page }) => {
  await page.goto("https://example.com");
  await expect(page).toHaveTitle(/Example/);
});

Phase 3 — Learn Playwright Core API

6. Navigation

await page.goto("https://example.com");
await page.waitForLoadState();
await page.waitForTimeout(3000);

This repo uses many fixed waits because the live systems can be slow or unpredictable.

7. Locators

page.getByRole("button", { name: "Hantar" })
page.getByRole("textbox", { name: "No. Pengenalan" })
page.getByText("Perkhidmatan ezHasil")
page.locator("#fileInput_single")

Recommended locator priority:

  1. getByRole
  2. getByLabel
  3. getByText
  4. locator() with stable IDs/classes
  5. XPath only if necessary

8. Filling forms

await page.getByRole("textbox", { name: "No. Pengenalan" }).fill("860125085432");
await page.getByRole("combobox").selectOption("1");
await page.getByRole("button", { name: "Hantar" }).click();

9. Waits

await page.getByText("Some text").waitFor({ state: "visible", timeout: 10000 });
await page.waitForTimeout(5000);
await page.waitForLoadState();

Better style when possible:

const button = page.getByRole("button", { name: "Faham" });
await button.waitFor({ state: "visible", timeout: 10000 });
await button.click();

Phase 4 — Understand This Repo’s Automation Flow

10. Main workflow

  1. Clear browser cache/cookies.
  2. Load input data from test-data/.
  3. Go to MyTax dev URL.
  4. Log in.
  5. Navigate to e-Duti Setem.
  6. New tab opens.
  7. Switch to new tab.
  8. Go to stamping upload page.
  9. Upload document.
  10. Fill stamping form.
  11. Submit.
  12. Extract SRN from URL/page.
  13. Save SRN and URL into log files.
  14. Repeat in a loop.
  15. Some specs continue to HITS for follow-up processing.

New tab pattern

const [newPage] = await Promise.all([
  page.context().waitForEvent("page"),
  page.getByRole("link", { name: "e-Duti Setem" }).click(),
]);

await newPage.waitForLoadState();
page = newPage;

11. Important systems

  • MyTax: Starting login portal. Base URL: https://mytax-dev.hasil.gov.my/web/
  • e-Duti / EDS: Stamping submission creation. Typical URL: https://eds-uat.hasil.gov.my/stamping/upload
  • HITS: Follow-up actions after SRN creation in some specs.

Phase 5 — Understand Project Files

12. Important config files

playwright.config.ts key settings:

timeout: 770000
fullyParallel: false
workers: 1
headless: false
viewport: null
screenshot: "only-on-failure"
video: "retain-on-failure"
trace: "retain-on-failure"

Meaning: tests are long-running, one worker by default, browser is visible and maximized, and debug artifacts are saved on failure.

ecosystem.config.cjs is used by PM2 for forever/restarting runs:

{
  name: "srn-dev-forever",
  script: "cmd.exe",
  args: "/c npx playwright test tests/SRN_dev.spec.ts",
  autorestart: true,
  restart_delay: 10000,
  time: true,
}

Important: writeFileSync() overwrites files. appendFileSync() adds to files. Be careful not to erase permanent logs accidentally.

Phase 7 — Debugging Playwright Failures

16. Common failure types

  • Selector not found: button/text changed, page did not load, wrong role/account, modal blocked the page, or session expired.
  • Navigation failed: network issue, backend slowness, authentication failure, or environment down.
  • Upload failed: file missing, selector changed, file input hidden/changed.
  • New tab not captured: waitForEvent("page") must happen before or at the same time as the click.

17. Use Playwright report

npm run report

Look for screenshot, video, trace, error stack, and failed locator.

18. Use trace viewer

npx playwright show-trace test-results/<trace-file>.zip

Phase 8 — Learn Maintenance Skills

19. Updating selectors

await page.getByRole("button", { name: /Hantar|Submit/ }).click();

20. Improving waits

await page.getByRole("button", { name: "Faham" }).waitFor({
  state: "visible",
  timeout: 10000,
});

21. Handling optional modals

const modalButton = page.getByRole("button", { name: "Ok" });

if (await modalButton.isVisible().catch(() => false)) {
  await modalButton.click();
}

22. Working with loops

for (let i = 1; i <= 40; i++) {
  console.log(`--- Loop iteration ${i} ---`);
}

When debugging, temporarily reduce loop count to 1, then restore it after testing.

Phase 11 — Worker1 / Worker2 Parallel Strategy

  • Worker1 usually writes to test-data/current-url-worker1.txt.
  • Worker2 writes to test-data/current-url-worker2.txt.
  • Worker2 runs with Edge, headless mode, and output to test-results-worker2.
npm run e2e-combine-penalti-without-penalty-worker2:one
npm run e2e-combine-penalti-without-penalty:staggered

The staggered command starts worker1, waits 60 seconds, then starts worker2 to reduce account/session collision and backend load.

Phase 12 — Adding a New Automation Spec

  1. Copy a similar spec.
  2. Rename carefully, for example tests/new-flow.spec.ts.
  3. Add package scripts.
  4. Add PM2 config.
  5. Test one run first.

Package scripts example

"new-flow:one": "playwright test tests/new-flow.spec.ts",
"new-flow:forever": "pm2 start ecosystem.config.cjs --only new-flow-forever",
"new-flow:logs": "pm2 logs new-flow-forever",
"new-flow:stop": "pm2 delete new-flow-forever"

PM2 config example

{
  name: "new-flow-forever",
  script: "cmd.exe",
  args: "/c npx playwright test tests/new-flow.spec.ts",
  autorestart: true,
  restart_delay: 10000,
  time: true,
}

Phase 15 — What to Avoid

  1. Do not run all bots unless you really want many jobs running.
  2. Do not overwrite srn-permanent-log.txt accidentally.
  3. Do not change worker1 and worker2 to write to the same file.
  4. Do not remove long waits unless you prove the live system is stable without them.
  5. Do not assume a failure means code is wrong; it may be session expiry or backend slowness.
  6. Do not use PM2 forever mode before confirming the spec works once.
  7. Do not change playwright.config.ts workers/headless settings casually.
